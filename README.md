# Zen Memo (静的ホスト対応・極小WYSIWYGメモ)

「思考を邪魔しない究極の白紙」を追求した、スタンドアロン動作可能な静的Webメモアプリケーション。

---

## 構成（触る前に読む）

```
zen-memo/
├── index.html          画面の骨格
├── manifest.webmanifest  PWA の名札（名前・色・アイコン・表示形式）
├── sw.js               Service Worker。単体ホストでだけ動く
├── icons/              PWA アイコン（円相・生成物）
├── css/
│   ├── base.css        文字組みと本文まわり
│   ├── themes.css      色のトークン（色はここだけで決める）
│   └── ui-variants.css 3つのUIスタイル・ドロワー・モーダル・トースト
└── js/
    ├── app.js          アプリの実体
    └── pwa.js          SW の登録と theme-color の追随だけ。本体には干渉しない
```

**js/app.js が唯一の実体。** 以前あった `db.js` / `editor.js` / `gist.js` / `image.js` / `theme.js` / `ui.js` は
どこからも読み込まれていない写しだったため削除した（`trash/` にある）。直すときは常に `app.js` を直す。
（`js/pwa.js` は PWA の外付けで、アプリの機能を持たない。落ちてもアプリは動く。）

`js/app.js` は classic script（`type="module"` ではない）。Tiptap だけは起動時に
`import('https://esm.sh/...')` で動的に読み込む。

## 特徴

1. **画面全体がテキスト領域**
   - 余計なヘッダーや枠線は一切なし。**先頭の `H1`** がメモのタイトルになる（複数あっても最初のものだけ）。
2. **Markdown ショートカット（Input Rules）**
   - `# `〜`#### ` ＋スペースで見出し1〜4
   - `- ` / `* ` ＋スペースで箇条書き、`1. ` ＋スペースで番号付き
   - `- [ ] ` / `[ ] ` ＋スペースでチェックボックス（タップで完了トグル）
   - `> ` ＋スペースで引用、```` ``` ```` でコードブロック、`---` で水平線
3. **数式（KaTeX）**
   - `$式$` … 閉じ `$` を打った時点でインライン数式に変わる。
     **`$` の内側が空白で始まる・終わるものは変換しない**ので、`ランチは $12 で、夕食は $30` のような
     金額や `echo $HOME と $USER` は数式にならない。変換させたくない `$` は `\$` と書く。
   - `$$` ＋スペース … ブロック数式の入力欄（プロンプト）が開く。
   - ツールバーの `∑` … **空の段落ならブロック数式、文中ならインライン数式**を挿入する。
   - 数式をタップすると LaTeX を編集できる（空にすると削除）。
   - **コードブロック／コードスパンの中の `$` には一切触らない。**
4. **自然なリスト・見出し操作**
   - 空のリスト項目で Enter / Backspace → リストを抜けて通常段落へ。
   - 見出しボタンはトグル（すでにその見出しなら通常段落に戻る）。
5. **モバイルキーボード対応**
   - `interactive-widget=resizes-content` と `visualViewport` で、キーボードの直上にメニューが吸着する。
   - テキストエリアだけが独立スクロールする。
   - ※ この最適化が効くのは **単体（最上位の文書）としてホストしたとき**。
     Itera OS の中の iframe で開いている間は OS 側のレイアウトが優先される。
   - 画面の拡大は禁止していない（`user-scalable=no` は外した）。
6. **画像**
   - クリップボードから貼り付け、またはファイル選択で挿入。
   - Canvas で長辺 1200px に縮小し WebP（非対応環境では JPEG）品質 82% で Base64 化。画像サーバー不要。
   - ただし Base64 は本文に直接入るため、**画像が増えると Gist 同期の上限（1ファイル 1MB）に当たる**。
     超えたものは送信を見送り、同期後に警告で知らせる。
7. **UIスタイル（自動切替＋3種類）**
   - **自動（既定）**: 画面幅 **720px 以上ならカプセル・ピル**、**未満ならコーナードック** を出す。
     しきい値は `UIManager.AUTO_BREAKPOINT`。`matchMedia` の change を監視していて、
     ウィンドウをまたいでリサイズした瞬間に差し替わる（設定を「自動」にしている時だけ）。
   - **カプセル・ピル**（中央下・展開式） / **コーナードック**（右下FAB＋ボトムシート） /
     **全幅ミニマルバー**（キーボード連動）を、設定から明示的に固定することもできる。
   - 設定値は IndexedDB の `ui_variant`（`auto` / `capsule` / `sheet` / `bar`）。
     `UIManager.setVariant()` が設定値の入口、`applyVariant()` が実際の DOM 反映で、
     **`applyVariant()` に `auto` を渡してはいけない**（`resolveVariant()` で解決してから渡す）。
   - **削除はどのスタイルでも可能**（一覧の各行のゴミ箱、カプセルのトレイ、コーナードックのシート）。
   - アイコンは**全て単色のインライン SVG**（線幅 1.8〜2）で統一する。
     絵文字はプラットフォームごとに勝手に彩色されて無彩色の統一感を壊すので、**使わない**。
8. **ブラウザの「戻る」で一覧に帰る**
   - 「一覧を開いた」＝ `?view=list`、「このメモを開いた」＝ `?note=<id>` を
     `MetaOS.nav.declare()` でホストに申告している。ホストのタブ履歴（＝ブラウザの戻る／進む）が
     そのまま画面の行き来になる。
   - 逆向きは `nav_changed` を購読して `applyRoute()` で反映する。
   - **反映中は履歴を積まない**（`_navApplying` フラグ）。積むと戻る→反映→また積む、で無限ループになる。
     同じ場所を連続で積まないための `_lastRoute` も同じ理由。
   - `MetaOS` が無い単体ホストではこの節はまるごと無効になり、他の機能には影響しない。
9. **書き出し（Markdown / バックアップ）**
   - **このメモを .md で保存**: 開いているメモを Markdown ファイルとして書き出す。
     設定画面のほか、コーナードックの「書き出し」からも呼べる。
   - **全メモを書き出す**: データベース全体を 1 つの JSON（`format: "zen-memo-backup"`）に。
     全メモの本文・作成／更新時刻と、見た目まわりの設定を含む。
   - **GitHub PAT はバックアップに含めない**（バックアップを渡した相手に鍵まで渡さないため）。
   - 保存先は Itera OS 上では `MetaOS.host.showSaveDialog()` で選ぶ。
     単体ブラウザ（MetaOS 無し）や保存に失敗した時は、通常のダウンロードに落ちる。
   - 書き出す前に `flushSave()` するので、**打ちかけの内容も必ず入る**。
10. **ローカルファースト ＋ Gist 明示同期**
    - 普段は IndexedDB に自動保存（400ms）。**メモの切替・タブを閉じる・裏に回す前に必ず書き切る。**
    - 「同期」を押した時だけ、1つの Gist の中に `<note-id>.md` と `manifest.json` として同期する。
11. **CSS カスタマイズ**
    - 設定画面からカスタム CSS を直接入力できる。

## 同期の決まりごと（Gist）

- `manifest.json` が唯一の索引。`notes`（生きているメモ）と `deleted`（削除の記録）を持つ。
- **更新時刻は塗り潰さない。** リモートから取り込んだメモは向こうの `updatedAt` のまま保存する
  （塗ると毎回押し返し合いになり、競合の判定もできなくなる）。
- **削除は伝わる。** 消したメモは `deleted` に印が残り、次の同期で Gist からも消える。
  印は 90 日で消える。だから**削除したメモが同期で復活することはない**。
- **両方で編集していたら、どちらも消さない。** リモートが新しい場合でも、
  前回同期より後に触れたローカル版は「〜（競合 日時）」という別のメモに退避してから上書きする。
- `manifest.json` が壊れていたら**同期を中止**する（黙って上書きしない）。
- 1MB を超えて GitHub が本文を切り詰めた場合は raw から取り直す。取れなければ取り込みを見送る。
- 同期直後、開いているメモの内容が変わっていたら**自動で開き直す**（次の打鍵で古い内容を書き戻さないため）。

**PAT について**: GitHub PAT は IndexedDB に平文で保存される（ブラウザ内のみ・外へは GitHub API にしか送らない）。
共用端末では登録しないこと。

## Itera OS で使うとき

- `window.MetaOS` があるときだけ、保存のたびに **`user/appdata/zen-memo/<id>.md` へ写しを書き出す**
  （5秒ほどまとめてから、front matter 付き）。削除すれば写しも消える。
- 写しは**バックアップと可視化のため**であり、読み戻しはしない。正はあくまで IndexedDB。
  これにより、メモがクラウド同期・エクスポートの対象に入り、OS 側からも中身が読める。
- 単体ホスト時（GitHub Pages など）は `MetaOS` が無いので、この処理は丸ごと無効になる。

## 動作に必要なもの

- **起動時にネットワークが要る。** エディタ本体（Tiptap）と KaTeX を CDN から読む。
  読めなかったときは白画面のままにせず、**理由と「再試行」を表示する**。
- 読み込みが終わるまで下部のツールバーは薄く表示され、押せない（押しても無反応、を避けるため）。
- 起動さえ済めば、以後の編集・保存はオフラインでも動く（同期だけは当然ネットワークが要る）。

## PWA（ホーム画面に入れる）

**効くのは単体ホストしたときだけ。** Itera OS の中は blob: なので `js/pwa.js` が登録そのものを見送る。
OS 内での動作はこれまでと一切変わらない。

- **条件**: https（または localhost）で配ること。GitHub Pages はこれを満たす。
- **道具立て**: `manifest.webmanifest`（名前・色・アイコン）／`sw.js`（キャッシュ）／`icons/`／`js/pwa.js`（登録）。
- **パスはすべて相対**（`start_url` / `scope` は `./`）。`user.github.io/<repo>/` のようなサブパスでも動く。
  `js/pwa.js` は自分自身の `src` からアプリの根を割り出すので、ページの URL 形にも依存しない。

### キャッシュの決まりごと（sw.js）

| 対象 | やり方 | 理由 |
| :-- | :-- | :-- |
| 画面（ナビゲーション） | ネットワーク優先・落ちたらキャッシュ | デプロイした新版がすぐ出る |
| 自前の css / js / icons | stale-while-revalidate | すぐ出して裏で新しくする |
| CDN（esm.sh / jsdelivr） | キャッシュ優先 | URL に版が入っている。**二度目の起動からオフラインで開ける** |
| api.github.com / gist の raw | **一切触らない** | 同期データを掴むと古い本文で上書きしうる |

- **デプロイのたびに `sw.js` の `VERSION` を上げる。** 上げ忘れても画面と資産は更新されるが、
  先読みキャッシュ（precache）が古いまま居座る。
- 新しい版は**次に開いたときから**反映される。入ったことはトーストで伝える。
- 様子がおかしいときは、コンソールで `zenClearCaches()` を呼んでから再読込する。

### アイコン

`icons/` の円相（enso）は `agent/work/2026-09/zen_memo_icons.html` で生成した。
色は paper テーマの `--bg-color` / `--text-color` をそのまま使っている。
作り直すときはこのファイルを spawn すれば 4 枚（192 / 512 / 512-maskable / apple-touch-180）が上書きされる。

### データの置き場所

**オリジンが違えば IndexedDB も別。** OS 内のコピーと GitHub Pages 版はデータを共有しない。
**行き来は Gist 同期で行う。** PAT は端末ごとに登録する（共用端末には入れない）。

## デプロイ方法

ビルドツール（Node.js / npm）は不要。フォルダごと静的ホスティングに置くだけで動く。
GitHub Pages / Cloudflare Pages / Vercel / Netlify / S3 など。

`index.html` / `css/` / `js/` に加えて、**`manifest.webmanifest` / `sw.js` / `icons/` も一緒に上げる**こと。
`sw.js` はアプリの根（`index.html` と同じ階層）に置く。1 階層でも深いと制御できる範囲が狭まる。
